1. Paddle IPv6 누락 P1 심각도 재판정

결론: P1 장애 요인이 맞습니다.

원인 분석: 에지 게이트웨이(Cloudflare)는 IPv6 요청을 지원하며, Paddle이 IPv6를 통해 웹훅을 전송할 경우 cf-connecting-ip 헤더에 IPv6 주소가 전달됩니다. 현재 코드는 data.ipv4_cidrs만 캐시하고 ipv4ToInt 함수를 통해 IPv4 형식만을 처리하므로, IPv6 주소가 유입되면 파싱에 실패하여 정상적인 결제 이벤트도 forbidden_source(403)로 거절하게 됩니다. 이는 결제 누락으로 직결되므로 치명적인 결함입니다.

2. PADDLE_IP_ALLOWLIST=off 완화 조치 검증

결론: 충분하고 안전한 임시 완화 조치입니다.

검토 내용: 해당 환경 변수를 off로 설정하면 소스 IP 검증 로직을 우회하지만, 직후에 실행되는 Paddle-Signature HMAC 서명 검증은 정상적으로 작동합니다. 서명 검증이 단일 장애점이 되지만, 암호학적 무결성이 보장되므로 IP 검증 누락으로 인한 가용성 저하를 즉각적으로 해결하기 위한 우회책으로 적절합니다.

3. RLS 정책 동적 쿼리 변경 무결성 검토

결론: 정책 의미(Semantics)는 변경되지 않으며 안전합니다.

검토 내용: 0102_rls_wrap_auth_uid.sql에서 auth.uid()를 (select auth.uid())로 래핑하는 것은, PostgreSQL 옵티마이저가 해당 STABLE 함수를 InitPlan으로 끌어올려 행(row) 단위가 아닌 구문(statement) 단위로 1회만 평가하게 강제하는 성능 최적화 기법입니다. 논리적 반환값은 쿼리 생명주기 동안 동일하게 고정되므로, 어떤 권한이나 결과 행도 변동되지 않습니다. 또한 트랜잭션 내 사후조건(Post-condition) 검사로 치환 실패 시 롤백되므로 안전장치도 확실합니다.

대상 커밋: 0126c9d1..cae2b7ca (2nd-B origin/main)

대상 파일: db/migrations/0103_persona_graph_capture.sql

1. 깨끗한 DB에서 0001~0103 순서 재생 통과 여부

정적 검증 결과: 0103 마이그레이션 정책 생성 구문에서 auth.uid()를 참조합니다. CI 환경에 auth 스키마가 없더라도 기존 99개 마이그레이션에서 이미 해당 함수를 광범위하게 사용하고 있으므로, 함수 모의(Mocking)가 이미 존재합니다. 따라서 순서 재생은 정상 통과합니다.

2. 기존 프로덕션 테이블 존재 시 DROP POLICY의 안전성

정적 검증 결과: 매우 안전합니다. 마이그레이션 하단에 do $check$ 블록이 있어 세 테이블의 정책(Policy) 개수가 정확히 3개인지 검증합니다. 기존 정책의 이름이 달라 삭제되지 않고 새 정책이 추가될 경우, 정책 수가 3개를 초과하여 예외가 발생하고 트랜잭션이 롤백됩니다. 따라서 의도치 않은 정책 중복 상태로 남지 않습니다.

3. public.users(id) FK 캡처의 라이브 환경 편차 동등성

정적 검증 결과: 운영상 동등합니다. public.users는 auth.users와 1:1로 동일한 ID를 공유하므로 참조 무결성은 동일하게 유지됩니다. 또한 프로덕션에는 이미 auth.users(id)로 테이블이 존재하므로 IF NOT EXISTS 조건에 의해 프로덕션 테이블의 FK가 변경되지 않아 운영에 영향이 없습니다.

4. src/lib/supabase/types.gen.ts의 타입 재생성 필요 여부

정적 검증 결과: 반드시 재생성이 필요합니다. types.gen.ts를 검색한 결과 FK 누락 수준이 아니라 persona_entity, persona_reasoning_trace, persona_relation 세 테이블의 타입 정의 자체가 완전히 누락되어 있습니다. TypeScript 환경에서의 안전한 접근을 위해 타입 재생성이 시급합니다.

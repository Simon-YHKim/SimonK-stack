**Segment B (편의 vs 소유 20-30대 KR)**: 클라우드 편의 좋아하지만 "내 파일 export 쉬움", "lock-in 없음", "markdown 소유"로 전환 시 신뢰↑. grand naming(Soul/Muse/Core)은 vague/Barnum으로 의심. humble + 구체 소유 언어가 신뢰.
**Segment C (장기 아카이버 / retention seeker)**: "저장" 행동 자체가 가치 신호("나중에 다시 봐야겠다"). 첫 캡처 후 "영구 보관·소유" 확인이 week1 retention의 핵심. 조회수 바이럴보다 저장/재방문 유도 카피가 장기 효용.

**Cross-check / Refute**: grand "Soul Core" "Muse" "Lumen" 시리즈는 "vague but personal" Barnum + "invasive feel" (AI가 모든 기록 access 시 psychosis 언급)로 반감 유발. 로컬=낭만 아님, "통제권 필요한 특수 목적"으로 포지셔닝해야 함. 클라우드 편의파도 "portability + sovereignty"를 honest하게 말하면 전환.

- KR 사례: Obsidian + 로컬 PC로 가족 건강기록·스마트워치 339만건 분석, "외부 기업 플랫폼에 ... 넘기지 않고", "내 PC의 Obsidian에 기록". 클라우드 API 전송 회피가 핵심 동기.

결론

후보 변경은 Paddle 웹훅에 서명 검증과 출처 IP 확인을 함께 요구하는 방어층을 추가한다. 로컬 검증에서는 병합을 막을 결함을 찾지 못했다.

다만 이 코드는 live api.paddle.com/ips만 조회한다. Paddle 문서는 요청 환경에 따라 IP 목록이 달라진다고 설명하므로, sandbox 웹훅 재생 검증에는 별도 주의가 필요하다.

위험

운영 전제

cf-connecting-ip가 실제 호출자 IP라는 전제는 커밋 메시지의 실측 근거와 맞지만, 운영 활성화 전 live Paddle dashboard replay로 반드시 확인해야 한다.

Sandbox 검증

Paddle 공식 문서는 live와 sandbox IP가 다르다고 설명한다. 현재 구현은 live URL만 사용하므로 sandbox replay를 그대로 돌리면 정상 이벤트도 차단될 수 있다.

롤백

문제가 생기면 PADDLE_IP_ALLOWLIST=off로 우회할 수 있다. 코드 롤백 없이 웹훅 수신을 복구하는 운영 스위치다.

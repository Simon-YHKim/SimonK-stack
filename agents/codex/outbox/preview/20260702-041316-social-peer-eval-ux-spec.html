이번 사이클은 오래된 open 요청 하나를 처리했습니다. 결과는 바로 구현 확정이 아니라, 성인 한정, 동의 기반, 사용자 검토 기반으로 좁힌 설계 제안입니다.

결과

친구 초대, 평가 제출, 본인 확인, 페르소나 노출 흐름을 정리했습니다.

권고

풀 소셜 기능이 아니라 초대 토큰 기반의 제한된 흐름부터 시작해야 합니다.

위험

제삼자 데이터, 미성년 가능성, 동의 범위가 핵심 위험입니다.

검증

허브 보드, 프로토콜, 디자인 문서, 페르소나 화면 구조를 읽었습니다.

제안 흐름

초대

사용자가 관계 맥락을 고르고 만료되는 초대 링크를 만듭니다.

제출

초대받은 사람은 관찰 가능한 행동만 짧고 구체적으로 남깁니다.

확인

사용자는 받은 내용을 읽고 참고, 보류, 숨김 중 하나를 고릅니다.

노출

수용한 신호만 별도 카드인 외부에서 본 나에 표시합니다.

핵심 설계 판단

항목판단이유
출시 범위성인 한정 또는 잠금 상태제삼자 데이터와 미성년 경로가 동시에 생겨 법무 검토가 필요합니다.
데이터 반영자동 반영 금지외부 관점은 참고 근거이며 사용자가 수용한 것만 자기 모델에 들어가야 합니다.
화면 배치페르소나의 별도 섹션자기보고, 도구 응답, 외부 관점을 섞으면 신뢰도가 흐려집니다.
시각 표현중립 신호와 출처 라벨점수 경쟁처럼 보이지 않게 관계 맥락과 관찰 수를 보여줍니다.

결론

새 EAS 프로필은 기존 preview 프로필을 보존하면서, QA 전용 preview-emulator 프로필에만 Android ABI를 arm64-v8a,x86_64로 넓힌 변경입니다. 에뮬레이터에서 arm64 전용 APK가 크래시하던 검증 공백을 메우는 목적과 맞고, 릴리즈용 preview 프로필은 그대로 유지됩니다.

네이티브 빌드 설정 변경은 고위험 변경으로 분류했기 때문에, 병합 가능 의견과 별개로 Antigravity 교차 검증을 요청했습니다. EAS 빌드 실행, 배포, 푸시는 하지 않았습니다.

검증 결과
항목결과근거
JSON 파싱통과eas.json을 Node로 파싱했습니다.
프로필 존재통과build.preview-emulator가 존재합니다.
Android 산출물통과android.buildType은 apk입니다.
ABI 범위통과QA 프로필은 arm64-v8a,x86_64, 기존 미리보기 프로필은 arm64-v8a입니다.
복제 정합성통과ABI 값을 제외하면 새 프로필은 기존 미리보기 프로필과 동일합니다.
공백 검사통과git diff --check에서 출력이 없었습니다.
병합 충돌통과git merge-tree에서 충돌 표식이 없었습니다.
범위와 제한
  • 변경 파일은 eas.json 하나입니다.
  • 커밋은 16dcce74, 기준 origin/main은 ef4490ff입니다.
  • 실제 EAS 빌드, 에뮬레이터 설치, 픽셀 검증은 수행하지 않았습니다.
  • 공개 클라이언트 환경값은 검토했지만 보고서에 원문 키 값을 재출력하지 않았습니다.
자기 패널
관점판단
찬성에뮬레이터 QA를 막던 ABI 불일치를 프로덕션 프로필을 건드리지 않고 해결합니다.
반대빌드 설정 변경은 실제 EAS 산출물 없이는 완전 검증이 아닙니다.
대안로컬 빌드만 쓰는 방법도 있으나, 재현 가능한 원격 QA 프로필을 두는 편이 반복 검증에 더 적합합니다.
판정차단 이슈 없음. 실제 빌드 전 Antigravity 확인을 받는 것이 맞습니다.

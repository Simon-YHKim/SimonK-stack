결론

새 main 전진분은 Paddle webhook 보안 강화와 RLS 정책 성능 migration입니다. 정적 검사는 통과했지만, Paddle IP allowlist가 현재 Paddle API의 IPv6 CIDR을 사용하지 않아 정상 webhook이 차단될 수 있습니다.

발견

Paddle IPv6 allowlist 누락

실시간 Paddle IP 응답은 IPv4 CIDR 6개와 IPv6 CIDR 1개를 반환했습니다. 현재 함수는 data.ipv4_cidrs만 읽고 ipv4ToInt 기반 검사만 수행합니다.

위험: Paddle이 IPv6 출발지로 webhook을 보내면 유효한 결제 이벤트가 forbidden_source 403으로 거절될 수 있습니다.

RLS migration 확인

migration은 pg_policies를 런타임 열거하고 ALTER POLICY를 사용하며, 트랜잭션과 사후조건을 포함합니다. 로컬 PostgreSQL replay는 실행하지 못했습니다.

권장 조치

Paddle webhook 허용 목록이 ipv6_cidrs를 포함하도록 보완하거나, Supabase edge 경로가 Paddle IPv4만 사용한다는 근거가 확인될 때까지 실가동 활성화를 보류하는 것이 안전합니다. 긴급 완화로는 PADDLE_IP_ALLOWLIST=off가 있으나 보안 강화를 우회하므로 임시 조치로만 취급해야 합니다.

검토 결론

Android 진단 APK 워크플로 변경은 목적과 범위가 일치하며, main 기준 병합 트리 충돌은 없었다. 수동 릴리스 게이트가 떠밀려 취소되는 문제를 줄이고, 진단 APK가 EAS production 플래그와 더 가깝게 빌드되도록 맞춘 변경으로 판단한다.

단, 브랜치는 최신 origin/main@ae20c7f5를 포함하지 않는다. Claude 병합 게이트에서 최신 main 위로 cherry-pick 또는 rebase 후 최종 GitHub Actions 실행 결과를 확인해야 한다.

확인 항목

항목결과근거
수동 실행 동시성통과workflow_dispatch는 github.run_id 기반 그룹을 사용해 대기 중 release-gate 빌드가 main push 진단 빌드에 밀리지 않는다.
main 수동 실행 차단통과workflow_dispatch가 main에서 실행되면 명시적으로 실패한다. 고정 tag 또는 release/* ref를 요구한다.
광고 플래그 미러링통과EXPO_PUBLIC_ENABLE_ADS: "true"가 Android 진단 빌드에도 들어간다. CTA 노출은 기존 capability gate에 남아 있다.
시크릿 노출통과새로 추가된 값은 public env 플래그이며, keystore나 운영 시크릿 리터럴은 추가되지 않았다.

검증

  • git diff --check origin/main...HEAD: 통과
  • git merge-tree --write-tree origin/main HEAD: 통과
  • 정적 패턴 검사: ref guard, per-dispatch concurrency, ads flag, keystore 리터럴 부재 확인
  • actionlint: 로컬 미설치로 실행하지 못함

찬성: Android 릴리스 워크플로는 native-safety 표면이고, 수동 dispatch가 main drift를 만들 수 있다는 문제는 실제 릴리스 게이트 품질에 직접 영향을 준다.

반대: GitHub Actions 전용 문법은 로컬 actionlint 없이 완전 검증하지 못했다. 또한 브랜치가 최신 main을 포함하지 않아 병합 직전 재확인이 필요하다.

판정: 차단 이슈는 발견하지 못했다. 최신 main 위 재적용과 GitHub Actions 원격 실행 확인을 Claude 병합 게이트 조건으로 남긴다.

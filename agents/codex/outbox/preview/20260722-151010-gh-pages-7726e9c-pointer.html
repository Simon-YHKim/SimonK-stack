배포 포인터 정합성 확인

이번 사이클은 새 제품 코드를 수정하지 않고, 최신 웹 정적 배포 브랜치가 현재 본선 커밋을 정확히 가리키는지만 확인했다.

판정 정합성 통과
본선 7726e9c3310c04d9eb6aa075cf248f719abcedae
배포 브랜치 01ad8897d6b8db0c357a51bd1ef8f7a08341fd26
검증 시각 2026-07-22 15:10:10 KST

핵심 결과

항목 확인값
본선 제목 fix(onboarding): convert Get started to a #680-safe bare Pressable (Fabric dead-touch) (#1128)
배포 제목 deploy: 7726e9c3310c04d9eb6aa075cf248f719abcedae 7726e9c3310c04d9eb6aa075cf248f719abcedae
판정 근거 배포 커밋 제목이 현재 본선 전체 SHA를 정확히 두 번 포함한다.
검증 명령
  • git fetch origin
  • git rev-parse --short=8 origin/main
  • git log -1 --oneline origin/main
  • git show --no-patch --format='%H%n%ct%n%s%n%b' origin/gh-pages
  • git rev-list --parents -n 1 origin/gh-pages
  • git ls-tree --name-only origin/gh-pages
검증 한계

origin/gh-pages는 정적 산출 브랜치이며 이 로컬 참조에서는 부모가 없는 형태로 확인되었다. 따라서 부모 커밋 기준 전체 diff check는 수행할 수 없었고, 이번 보고서는 배포 포인터 정합성 확인으로 한정한다.

섹션 35 자기 패널
  • 관점 A: 배포 제목이 본선 전체 SHA를 정확히 포함하므로 포인터 정합성은 정상이다.
  • 관점 B: 정적 산출 브랜치는 소스 브랜치와 계보가 달라 소스 회귀 검증으로 확대하면 안 된다.
  • 관점 C: 부모 없는 산출 커밋의 전체 diff 품질 검증은 제한적이므로 release QA 통과로 과장하지 않는다.

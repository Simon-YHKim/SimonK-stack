/vibe 실제 프로필 링크는 확인, 설치는 보류

최신 2.12.35 후보와 현재 사용자 프로필의 Core 링크·네이티브 플러그인 목록을 비교했다. Claude·Codex의 /vibe 본문은 이전 버전이고 후보 플러그인 5개는 양쪽 모두 미등록이다. 사용자 스킬 링크·플러그인 등록은 변경하지 않았다.

검사 범위와 결과

scripts/vibe_host_preflight.py는 Claude Core 정션 5개, Codex 정션 2개, .agents 별칭 1개를 읽었다. 7개 정션의 직접 대상은 명시한 기존 후보 루트와 일치하고 별칭도 Claude flat 경로를 가리켰다. 다른 본문은 Claude와 Codex의 vibe/SKILL.md 2개이며 다른 Core 5개는 후보와 같은 해시였다. 스크립트는 링크 이동·교체·삭제·모델 호출·계정 조회를 수행하지 않는다.

후보의 전체 SKILL.md와 flat 설치본을 비교하면 Claude 182개 중 일치 4·변경 134·미설치 44, Codex 안전 부분집합 177개 중 일치 4·변경 128·미설치 45다. 따라서 링크 구조가 정상이어도 전체 스킬은 현재 후보로 설치되지 않았다.

claude plugin list --json와 codex plugin list --json의 현재 관측값에서는 후보 네이티브 플러그인이 각 0/5였다. 검사기는 목록을 메모리에서 받아 후보의 정확한 이름·버전·활성 상태와 대조하고 원본 목록이나 사용자 경로를 보고하지 않는다. 목록 일치가 곧 캐시 바이트 검증은 아니다.

Windows Python 3.11의 정션 판별 오류를 수정했다. 결과 JSON은 절대 경로를 출력하지 않고 대상 일치 여부와 해시만 남긴다. 손상된 네이티브 manifest는 차단 결과로 처리한다.

네 SHA-256 digest를 별도 고정값으로 입력하면 source·Claude bundle·Codex overlay·안전 부분집합의 전체 파일 바이트와 출처 연결을 호스트 스캔 전에 확인한다. 2.12.35 후보는 4/4 일치했고 잘못된 source pin은 즉시 차단됐다. digest를 생략하거나 일부만 주면 바이트 검증 성공으로 보고하지 않는다. 이 검사는 서명·실행 중 불변성·설치된 플러그인 캐시 검증이 아니다.

검증과 한계

새 검사기의 RED 실패를 관측한 뒤 구현했다. 검사기·패키지·main 릴리스 펜스 107개가 Python 3.11과 3.12에서 각각 통과했고, 마지막 검증기 누락 예외 처리 후에는 검사기 집중 회귀 22개가 두 버전에서 각각 통과했다. 마지막 변경 후 108개 전체 묶음을 재실행했다고 주장하지 않는다. Windows 실제 정션 fixture를 포함하고, 심볼릭 링크 생성 불가를 성공적인 skip으로 처리하지 않는다. 정확한 source·Claude·Codex overlay·안전 부분집합 영수증 4/4를 기존 검증기로 확인했고 잘못된 digest는 차단했다. 전체 저장소 테스트나 모델·Bot·이미지 실호출은 수행하지 않았다.

전체 flat 감사는 SKILL.md 바이트, 네이티브 감사는 목록 메타데이터에 한정된다. 실제 명령 우선순위·적재, 스크립트와 자산, 모델·effort 선택 품질, 계정 청구, 이미지·Bot 전달은 확인하지 않았다. 따라서 rollout_gate=blocked와 installation_ready=false다. 자동충전·결제 설정은 변경하지 않았다. 별도 사용량 확인을 위해 만든 빈 임시 디렉터리의 Claude 로컬 신뢰 승인과 세션 메타데이터는 생겼으며, 앞선 실패한 제한 평가 1건의 실제 청구액은 확인되지 않았다.

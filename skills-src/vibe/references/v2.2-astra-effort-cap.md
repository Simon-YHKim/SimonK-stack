# v2.2 — gpt-6-astra 편입과 Orca effort 상한 (2026-09-06, 09-13 재확인)

> SKILL.md 에서 옮겼다(2026-09-13) — SimonK-stack CI 의 본문 500줄 상한(E007) 때문이다. 내용은 그대로다.


codex 계열에 GPT-6 세대 좌석이 열렸다. `~/.codex/models_cache.json` 에서 **priority 1**, *"Our most capable model for complex, demanding work."* `~/.codex/config.toml` 의 기본 모델도 이미 `gpt-6-astra` 다(직전 값은 `gpt-5.6-sol`).

바뀐 것은 셋이다.

1. **레인 추가 + B 2순위 승격.** 판단(B)의 2순위가 `gpt-5.6-sol` → `gpt-6-astra`. 부수 효과로 sol 이 B 목록에서 빠지면서 **코디네이터 겸임 충돌이 구조적으로 0** 이 됐다.
2. **인가 게이트 승격.** 보안 — 비즈로직·인가가 `gpt-5.6-terra @high` → **`gpt-6-astra @xhigh`** (Simon 결정 2026-09-06). Orca 에서 이 모델로 갈 수 있는 최상단이다.
3. **effort 를 '정책'과 '물리적 상한'으로 쪼갰다.** 아래가 이 버전의 핵심이다.

> ### ⚠ 왜 astra 에 `max`·`ultra` 가 안 되는가 — 원인 규명 완료
>
> "ultra 도 좋지만 max, xhigh 역시 좋아"는 astra 에 대해서는 **xhigh 만 성립한다.** 추측이 아니라 Orca 원본 코드에서 확인했다 — 앱 번들(`app.asar`, v1.4.193)과 저장소 HEAD 양쪽에서 같은 파일을 읽었다:
>
> ```js
> // src/shared/agent-session-option-catalog-claude-codex.ts
> const CODEX_SESSION_OPTION_CATALOG = {
>   models: [
>     { id: 'gpt-5.6-sol',   options: [codexEffort('ultra')] },
>     { id: 'gpt-5.6-terra', options: [codexEffort('ultra')] },
>     { id: 'gpt-5.6-luna',  options: [codexEffort('max')]   },
>     { id: 'gpt-5.5',       options: [codexEffort('xhigh')] },
>     { id: 'gpt-5.2-codex', options: [codexEffort('xhigh')] }
>   ],
>   unknownModelOptions: [codexEffort('xhigh')]   // ← 목록에 없는 모든 모델
> }
> ```
>
> **`gpt-6-astra` 와 `gpt-daybreak-blue-latest` 는 이 목록에 아예 없다.** 그래서 둘 다 “모르는 모델”로 떨어지고, 모르는 모델의 상한이 `xhigh` 다. 실제로 존재하지도 않는 `gpt-9-nonexistent` 가 정확히 같은 상한을 받는 것이 그 증거다.
>
> Orca 소스의 주석이 이게 **의도**임을 밝힌다: *“Codex model access depends on auth. Keep this seed short and allow unknown persisted ids to pass through instead of claiming a complete list.”* 계정마다 쓸 수 있는 모델이 달라서 완전한 목록을 주장하지 않겠다는 것이다. **버그가 아니라 설계된 폴백이다.**
>
> **그래서 Orca 를 올려도 안 풀린다.** 설치본 1.4.193 · 최신 1.4.197(2026-09-04)인데, 저장소 HEAD 의 그 파일도 여전히 같은 다섯 줄이다(`gpt-6-astra` 는 테스트 픽스처에만 나온다). 버전 문제가 아니다.
>
> ✅ **2026-09-13 재확인 — 1.4.200 에서도 그대로다.** 설치본이 1.4.193 → **1.4.200** 으로 올라갔길래 번들을 다시 읽었다(`app.asar` 안 카탈로그 바이트를 직접 훑었다). 다섯 줄이 글자 그대로 같다: `sol:ultra · terra:ultra · luna:max · gpt-5.5:xhigh · gpt-5.2-codex:xhigh`, 그리고 `unknownModelOptions:[xhigh]`. **astra·daybreak 은 여전히 목록에 없다.** 버전이 세 번 올라도 안 바뀌었으니 '다음 버전에서 풀리겠지'로 미루지 말 것 — 필요하면 codex 직행이거나 업스트림 요청이다.
>
> | 경로 | astra 에서 되는 effort |
> |---|---|
> | Orca 워커 | `minimal` `low` `medium` `high` **`xhigh`** — `max`·`ultra` 는 `invalid_argument` |
> | codex CLI 직행 | 위 전부 + **`max` `ultra`** — 실호출로 확인 |
>
> **`ultra` 로 가는 길은 셋뿐이다** — ① `gpt-5.6-sol @ultra`(카탈로그에 있는 모델로 내린다) · ② `run_codex_exec(..., effort="ultra")` 로 codex CLI 직행(워커가 아니다 — 격리·게이트·원장 없음) · ③ Orca 에 astra 를 seed 에 넣어달라고 업스트림에 올린다.

**측정은 이제 무료다.** `python scripts/routing.py --probe-efforts --task <실재 task_id>` 가 워커를 띄우지 않고 허용목록을 다시 잰다 — Orca 의 검증 순서가 `task → effort → worktree → 기동` 이라, 없는 worktree 이름을 같이 주면 effort 판정만 돌려받는다. 새 모델이 나올 때마다 이걸 먼저 돌린다.
